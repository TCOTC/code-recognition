# 06 插件设计方案

## 1. 总体流程

```
用户粘贴 / 输入
  └─ 触发判定：目标是不是“无语言的代码块”？是不是用户锁定的块？长度够不够？
       └─ 采样：≤8KB 取全文；>8KB 取头 4KB + 尾 4KB
            └─ 第 1 层：betlang wasm 推理（毫秒级）→ 48 类概率分布
                 ├─ 置信度过滤（0.2 / 0.2 分组落差）
                 ├─ 映射到 hljs 语言名（映射不到就顺延下一个候选）
                 └─ 命中 → 通过 /api/transactions 写回
            └─ 第 2 层（第 1 层失败时）：关键词规则表打分
                 └─ 唯一高分命中 → 写回
            └─ 都不命中 → 什么都不做（保持空白语言）
```

## 2. 触发策略

| 触发点 | 是否默认启用 | 说明 |
|---|---|---|
| `paste` 事件，且目标是无语言代码块 | ✅ | 主场景。不 `preventDefault`，旁路监听，粘贴照常进行 |
| 用户手动触发（命令 / 语言下拉里的“自动识别”项） | ✅ | 用 `addCommand` + `code-language-update` 注入列表项 |
| 键入后在空闲期识别（防抖 800 ms） | ❌（可配置） | 复刻 Zed 的 on-type 体验，但笔记场景收益低、开销高，默认关 |
| 编辑器加载已有无语言代码块 | ❌ | 会大量触发旧文档的识别，风险高，默认关 |

防抖与竞态处理（照抄 Zed 的三条规则）：

1. 每次触发先 `clearTimeout` 再 `setTimeout`；
2. 定时器到期后**重新校验**：块是否还存在、语言是否已被用户改掉、长度是否够；
3. 推理完成后校验**内容快照是否变化**，变了就丢弃结果。

## 3. 采样

```ts
const SAMPLE_BLOCK_SIZE = 4096;

function sample(code: string): Uint8Array {
  const bytes = new TextEncoder().encode(code);
  if (bytes.length <= SAMPLE_BLOCK_SIZE * 2) return bytes;
  const head = bytes.subarray(0, SAMPLE_BLOCK_SIZE);
  const tail = bytes.subarray(bytes.length - SAMPLE_BLOCK_SIZE);
  const out = new Uint8Array(head.length + tail.length);
  out.set(head, 0);
  out.set(tail, head.length);
  return out;
}
```

注意：betlang 内部还会自己裁成「前 1 KB + 后 1 KB」，所以这里不需要更复杂的采样。
但如果第 2 层规则表要全文扫描，**不要把全文喂给规则表**——先用 `sample()` 的结果。

最小长度：与 Zed 保持一致，`code.trim().length < 20` 直接返回（betlang 自己也有“少于 8 个非空白字节不检测”的硬门槛）。

## 4. 第 1 层：betlang 决策逻辑

直接移植 `02-Zed实现调研.md` 第 4 节的算法，改动点只有一处：

> Zed 用 `language_registry.available_language_for_name(...)` 校验“本编辑器是否支持该语言”；
> 我们改为用 `hljs.getLanguage(name)` 校验，并且**优先从映射表里拿到 hljs 名**。

```ts
const MIN_CONFIDENCE = 0.2;        // 候选最低置信度
const CONFIDENCE_GAP = 0.2;        // 分组之间的落差
const SWITCH_GAP     = 0.5;        // 改语言所需的领先优势

function decide(scores: Map<string, number>, currentLang: string): string | null {
  // betlang 输出已按分数降序，这里按顺序遍历
  const confirmed: Array<[number, string]> = [];
  let pending: Array<[number, string]> = [];
  for (const [slug, score] of sortedDesc(scores)) {
    if (pending.length && pending[pending.length - 1][0] - score >= CONFIDENCE_GAP) {
      confirmed.push(...pending);
      pending = [];
    }
    if (score < MIN_CONFIDENCE) break;
    pending.push([score, slug]);
  }
  // 最后一组天然被丢弃（与 Zed 一致：要求 top 组后面有明确落差）

  let best: [number, string] | null = null;
  for (const [score, slug] of confirmed) {
    const hljsName = BETLANG_TO_HLJS[slug];        // 见第 5 节
    if (!hljsName) continue;                       // 映射不到，顺延下一个候选
    if (!window.hljs?.getLanguage(hljsName)) continue; // hljs 不认识，顺延
    best = [score, hljsName];
    break;
  }
  if (!best) return null;

  const current = BETLANG_TO_HLJS[currentLang === "" ? "" : currentLang] ?? currentLang;
  if (current === best[1]) return null;

  const currentScore = scores.get(/* betlang slug of current */ "") ?? undefined;
  if (currentScore !== undefined && best[0] <= currentScore + SWITCH_GAP) return null;
  return best[1];
}
```

## 6. 第 2 层：关键词规则表（推荐实现）

目标：用**一次线性扫描**覆盖 betlang 覆盖不到的长尾语言，成本是微秒级。

```ts
interface Rule { lang: string; score: number; test: RegExp | ((code: string) => number); }

const RULES: Rule[] = [
  {lang: "fortran",  score: 3, test: /\b(?:(?:END\s+)?(?:PROGRAM|SUBROUTINE|MODULE|FUNCTION))\b|\bIMPLICIT\s+NONE\b/i},
  {lang: "ada",      score: 3, test: /\b(?:procedure|package\s+body|with\s+\w+\s*;|end\s+\w+\s*;)\b/i},
  {lang: "pascal",   score: 3, test: /\b(?:program|procedure|begin\b[\s\S]*\bend\.|var\s+\w+\s*:\s*\w+)\b/i},
  {lang: "matlab",   score: 3, test: /^\s*function\b|\bend\s*$|\b(?:clc|clear\s+all|disp)\b/m},
  {lang: "graphql",  score: 3, test: /\b(?:type|query|mutation|scalar|interface|input)\s+\w+\s*(?:\(|\{|implements)/},
  {lang: "protobuf", score: 4, test: /\bsyntax\s*=\s*"proto[23]"\s*;|\bmessage\s+\w+\s*\{|\brpc\s+\w+/},
  {lang: "nginx",    score: 3, test: /\b(?:server|location|upstream|proxy_pass|listen)\b[\s\S]*\{/},
  {lang: "crystal",  score: 2, test: /\b(?:def\s+\w+.*\n\s*end|require\s+"\w+"|module\s+\w+\n)/},
  {lang: "nim",      score: 3, test: /\b(?:proc|func|template|macro)\s+\w+\s*[\(\[].*?\)\s*[:=]|\becho\b/},
  {lang: "glsl",     score: 4, test: /\b(?:void\s+main\s*\(\s*(?:void)?\s*\)|gl_Position|uniform\s+\w+|#version\s+\d+)/},
  {lang: "vim",      score: 4, test: /^\s*(?:set|let|map|nnoremap|autocmd|function!?)\b/m},
  {lang: "wasm",     score: 4, test: /^\s*\(\s*(?:module|func|memory|table)\b/m},
  {lang: "erb",      score: 3, test: /<%[-=]?[\s\S]*?%>/},
  {lang: "handlebars", score: 3, test: /\{\{[#/>]?\w+/},
  {lang: "scss",     score: 2, test: /\$[\w-]+\s*:|@(?:mixin|include|extend|use|forward)\b/},
  {lang: "less",     score: 2, test: /@[\w-]+\s*:|\.\w+\s*\(\s*@/},
  // ... 其余长尾按 `appendix/数据附录.md` 的“两者都覆盖不到的 127 种”逐个补
];

function ruleDetect(code: string): string | null {
  let best: {lang: string; score: number} | null = null;
  let tie = false;
  for (const rule of RULES) {
    const s = typeof rule.test === "function" ? rule.test(code) : (rule.test.test(code) ? rule.score : 0);
    if (s <= 0) continue;
    if (!window.hljs?.getLanguage(rule.lang)) continue;
    if (!best || s > best.score) { best = {lang: rule.lang, score: s}; tie = false; }
    else if (s === best.score) tie = true;
  }
  return best && !tie && best.score >= 3 ? best.lang : null;
}
```

实现建议：

- **规则只在前一层失败时运行**，避免污染主流语言的判断；
- 规则表写成一个单独的 TS 模块（如 `src/lang-rules.ts`），便于后续增删；
- 每条规则都要有正/负样例测试，避免出现“某条规则吃掉所有内容”的情况；
- 规则命中的语言必须存在于 `hljs.listLanguages()`，启动时校验一次并告警。

### 6.1 为什么不用 `hljs.highlightAuto` 当兜底

已经实测过，结论是否定的（数据见 `03-识别引擎选型.md` 第 8 节）：

| 方案 | 准确率（103 个真实长尾文件） | 平均耗时 |
|---|---|---|
| 关键词规则表（本节方案） | 61.2% | 0.094 ms |
| `highlightAuto`（201 语言全量） | 14.6% | 37.7 ms |
| `highlightAuto`（去掉 moonbit、dns 后 153 候选） | 33.0% | 22.9 ms |

根因是 `relevance` 分数**跨语言不可比**：SiYuan 的 `third-languages.js` 引入的 `moonbit`
语法声明了 144 个泛用关键字，任何代码都能把它刷到最高分，导致 Rust / Python / Go
都被判成 MoonBit。这不是调参能解决的问题。

如果将来要复用 `highlightAuto`，**前提是候选集已经被收窄到十几个**（那种情况下它
准确率 81.6%、耗时 1.5 ms）。个别语法特征极强的语言（如 `.wat` 9/10）可以用它做特例，
但要单独设白名单并逐个验证。

## 7. 状态管理（防止覆盖已有语言）

自动识别只处理语言文本严格为空的代码块，任何已有语言（包括 `plaintext`）都不覆盖，因此不维护手动锁定或自动识别来源状态。显式命令和菜单操作允许覆盖已有语言。

## 9. 边界情况与对策

| 情况 | 对策 |
|---|---|
| 纯 `- item` 列表 | betlang 可能给出 Markdown 或 YAML。有明显代码特征时使用 `0.2` 最低置信度，否则提高到 `0.6`；所有结果仍需满足 `0.2` 的置信度落差 |
| 粘贴的是带围栏的 Markdown（```rust） | SiYuan 已经会创建带语言的代码块，检测前先判断语言是否为空，非空直接跳过 |
| 代码块里有超过 8 KB 的内容 | 采样头尾各 4 KB，与 Zed 一致 |
| 语言名在 hljs 里不存在（cobol / gemfile / gemspec） | 映射表里写 `null`，跳过该候选、顺延下一个 |
| `hljs` 尚未加载（懒加载） | 检测前若 `window.hljs` 未就绪，先触发一次代码块渲染或等待 `window.hljs` 出现；拿不到就放弃写入 |
| 只读块 / 发布模式 | `areProtylePluginExtensionsEnabled` 为 false 时不触发；写入前再校验块不在只读文档中 |
| 用户正在撤销 | 写入必须走 `/api/transactions` 并带 `undoOperations`，保证一次 Ctrl+Z 能还原语言 |
| 混合选择 / 同时多个代码块 | 显式命令和块菜单递归收集选中块中的代码块，按块 ID 去重并合并为一个事务 |
| 与 `code-languages` 插件共存 | 它只改下拉列表；我们直接写块，互不冲突。但若两插件都注入列表项，需要测试顺序 |
| 移动端粘贴 | 事件路径一致，但 `files` / `localFiles` 可能为空，注意判空 |
| betlang 返回空（输入太短/全空白） | 视为未识别，不做任何写入 |

## 10. 伪代码骨架

```ts
export default class CodeRecognition extends Plugin {
  private cfg: CodeRecognitionConfig;
  private engine: BetlangEngine;          // 懒加载 wasm 的封装
  private locked = new Set<string>();
  private auto = new Set<string>();

  async onload() {
    this.cfg = {...DEFAULT_CONFIG, ...(await this.loadData(STORAGE_NAME))};
    this.eventBus.on("paste", this.onPaste);
    this.eventBus.on("code-language-change", this.onLanguageChange);
    this.addCommand({
      langKey: "detectLanguage",
      hotkey: "",
      editorCallback: (protyle) => this.detectCurrentBlock(protyle, true),
    });
  }

  onunload() {
    this.eventBus.off("paste", this.onPaste);
    this.eventBus.off("code-language-change", this.onLanguageChange);
  }

  // 旁路监听：不 preventDefault，粘贴照常进行
  private onPaste = (event: CustomEvent<IEventBusMap["paste"]>) => {
    if (!this.cfg.enabled || !this.cfg.detectOnPaste) return;
    const {protyle, textPlain} = event.detail;
    const block = currentCodeBlockElement(protyle);   // 见 05 文档 5.1
    if (!block) return;
    const id = block.getAttribute("data-node-id");
    if (this.locked.has(id)) return;
    const existing = readLanguage(block);
    if (existing && this.cfg.skipExistingLanguage && !this.auto.has(id)) return;
    setTimeout(() => this.detectAndApply(protyle, id, textPlain), 0); // 等原生粘贴落地
  };

  private onLanguageChange = (event: CustomEvent<IEventBusMap["code-language-change"]>) => {
    for (const el of event.detail.languageElements) {
      const id = closestBlockId(el);
      if (id) { this.locked.add(id); this.auto.delete(id); }
    }
  };

  private async detectAndApply(protyle: IProtyle, blockId: string, code: string) {
    if (code.trim().length < this.cfg.minLength) return;
    const lang = await this.detect(code);
    if (!lang) return;
    // 再次校验：块还在、内容没变、语言没被改
    await this.applyLanguage(protyle, blockId, lang);   // 见 05 文档 5.2 方案 A
    this.auto.add(blockId);
  }

  private async detect(code: string): Promise<string | null> {
    const scores = await this.engine.scores(sample(code));   // 懒加载 wasm
    return decide(scores, /* 当前语言 */ "") ?? (this.cfg.enabledRules ? ruleDetect(code) : null);
  }
}
```

## 11. 测试计划

必须覆盖（对应 `01-需求与约束.md` 第 7 节的成功标准）：

1. 每种主流语言的真实片段（建议从 SiYuan 仓库自身源码里取 `.rs/.ts/.go/.py/...` 片段）；
2. 反例：中文散文、日志、JSON 数据、纯 `- item` 列表、表格文本；
3. 交互：粘贴→识别、二次粘贴→改写、手选语言→锁定、撤销→语言回滚；
4. 性能：10 KB 代码块的识别耗时、连续粘贴 20 次的累计耗时；
5. 兼容：与 `code-languages` 插件共存、移动端、只读文档；
6. 回归：`hljs.listLanguages()` 的 201 个语言名逐个验证映射表（写一个一次性脚本）。
