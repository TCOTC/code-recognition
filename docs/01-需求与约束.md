# 01 需求与约束

## 1. 用户需求（原话）

> 我要支持 `D:\CodeProjects\siyuan` 里支持的 hljs 里的那些语言，对识别速度要求高。

拆解：

- **范围** = SiYuan 实际加载的 highlight.js 语言集合，不是“所有编程语言”。
- **速度优先** = 识别不能成为输入/粘贴的负担。
- **隐含需求** = 识别结果必须能直接喂给 `hljs.getLanguage(name)`，否则高亮不生效。

## 2. 目标环境

| 项 | 值 | 说明 |
|---|---|---|
| 最低 SiYuan 版本 | `3.7.0` | 已在 `plugin.json` 声明。**必须保持或提高，不能降低**：本方案依赖 3.7.0 才有的 `paste` 插件事件与 `code-language-*` 扩展事件（见 `05-SiYuan插件接口.md`）。 |
| 本机开发版本 | SiYuan `3.8.4-alpha.4`（源码 `D:\CodeProjects\siyuan`） | 所有 SiYuan 源码引用都基于这个版本 |
| 前端形态 | `desktop` / `mobile` / `browser-desktop` / `browser-mobile` / `desktop-window` | 即 Electron 渲染进程 + 浏览器 + 移动端 WebView，**三者都必须能跑 wasm** |
| 后端形态 | windows / linux / darwin / ios / android / harmony / docker | 本方案不在 kernel 侧执行任何逻辑，后端无关 |
| 测试工作空间 | `D:\Admin\Desktop\测试空间` | 已装好多个插件，便于验证共存 |

## 3. 语言范围（核心约束）

SiYuan 的语言列表来自运行时动态加载的 highlight.js，而不是 npm 依赖：

```
app/src/protyle/render/highlightRender.ts:34
    addScript(`${cdn}/js/highlight.js/highlight.min.js?v=11.12.0`, "protyleHljsScript")
    addScript(`${cdn}/js/highlight.js/third-languages.js?v=2.0.1`, "protyleHljsThirdScript")
```

本地实际文件（随应用分发）：

```
D:\CodeProjects\siyuan\app\stage\protyle\js\highlight.js\highlight.min.js      1,026,391 B
D:\CodeProjects\siyuan\app\stage\protyle\js\highlight.js\third-languages.js       33,655 B
```

【实测】用 Node 加载这两个文件后调用 `hljs.listLanguages()`：

```
hljs version = 11.12.0
total languages = 201
```

补充事实：

- 201 是**注册名**（含别名），例如 `bash` / `shell`、`ini` / `dns`、`dos` / `batch` 都各算一个。独立语法数约 190。
- 下拉框的候选是 `Constants.ALIAS_CODE_LANGUAGES.concat(hljs.listLanguages()).sort()`（`app/src/protyle/toolbar/index.ts:1939`），其中
  `ALIAS_CODE_LANGUAGES = ["js", "ts", "html", "toml", "c#", "bat"]`（`app/src/constants.ts:935`）。
- 另有一组**不是 hljs 语言**的渲染节点：`SIYUAN_RENDER_CODE_LANGUAGES = ["abc", "plantuml", "mermaid", "flowchart", "echarts", "mindmap", "graphviz", "math"]`（`app/src/constants.ts:938`）。这些由 Mermaid 等渲染器接管，**自动识别必须永不选择它们**。
- 语言写入代码块后，SiYuan 只用它做两件事：`hljs.getLanguage(language)` 查表高亮，以及判断是否属于 `SIYUAN_RENDER_CODE_LANGUAGES` 走渲染器分支。**识别输出必须是 hljs 认识的字符串**，否则该语言名会被当作自定义语言原样保留但不报错（`app/src/protyle/render/highlightRender.ts:70` 有 `if (!window.hljs.getLanguage(language))` 的兜底路径）。

完整 201 语言清单见 `appendix/数据附录.md`。

## 4. 性能指标

以本机（Windows，Node 25.9.0）实测为基准，目标是**比现有可选方案快一个数量级以上**：

| 指标 | 目标值 | 参考值 |
|---|---|---|
| 单次识别耗时（≤8 KB 代码） | ≤ 10 ms | hljs `highlightAuto` 全量 19.5 ms（338 B）/ 176 ms（7 KB） |
| 冷启动（首次加载引擎） | ≤ 300 ms，且异步、不阻塞首屏 | wasm 模块体积预期几十~几百 KB（【待验证】） |
| 常驻内存 | ≤ 2 MB | 模型权重 47 KB + 推理 scratch（见 `04-betlang集成规格.md`） |
| 网络请求 | 0（完全离线） | Magika 需要联网拉 3 MB 模型 |
| 输入阻塞 | 0，必须异步或在空档期执行 | 见 `06-插件设计方案.md` 的触发策略 |

## 5. 正确性要求

1. **绝不覆盖用户显式选择**：用户通过语言下拉框选过语言（包括选“清除”）后，该代码块不再自动改。
2. **低置信度不猜**：识别不出就保持原样，宁可不动也不要设错语言。
3. **不确定的歧义要放过**：Markdown / YAML 的裸列表（`- item`）是已知歧义点，需要通过统一的置信度门槛与落差判定，置信度充分时允许在代码块中识别为 Markdown。
4. **不能破坏撤销**：语言变更要能被 Ctrl+Z 撤销，不能污染撤销栈顺序。
5. **不能影响既有插件**：`code-languages` 插件已经监听了 `code-language-update` / `code-language-change`，两者必须能共存。

## 6. 非目标

- 不做二进制/文件类型识别（那是 Magika 的领域，本项目不需要）。
- 不做“整篇文档自动识别”，只处理代码块。
- 不做语言服务器、不做格式化、不做代码执行。
- 不修改 SiYuan 内核，不依赖未公开的内部函数（`transaction()`、`highlightRender()` 等内部函数插件拿不到，见 `05-SiYuan插件接口.md`）。

## 7. 成功标准（可测）

- [ ] 粘贴一段 Rust 代码到空白代码块 → 代码块语言自动变成 `rust` 并高亮。
- [ ] 粘贴一段 Go 代码到已有 `rust` 语言的代码块（该语言是**自动识别**得来的）→ 语言跟着变成 `go`。
- [ ] 用户手动选了 `python` 之后再粘贴 Go 代码 → 语言保持 `python` 不变。
- [ ] 粘贴中文散文 → 语言保持为空；粘贴置信度充分的 Markdown 列表 → 语言设置为 Markdown。
- [ ] 在 100 KB 代码块上粘贴 → 不卡顿，识别在后台完成（采样策略见 `06-插件设计方案.md`）。
- [ ] 断网状态下功能完全正常。
- [ ] 移动端（`frontends: mobile`）可用。

## 8. 已知的项目级约束

- 插件要能上架集市，`plugin.json` 的 `version` / `minAppVersion` / `displayName` / `description` / `readme` 必须齐备，且随每次发布递增 `version`。
- `README.md` 与 `README.zh-CN.md` 现在是**空文件**，上架前必须写。
- 当前工作空间内的插件是被直接加载的源码目录；生产打包走 `pnpm build` → `package.zip`（含 `dist/`）。
- 发包用的 webpack 配置**只拷贝白名单文件**（`plugin.json` / `icon.png` / `preview.png` / `README*.md` / `i18n/`），**新增的 `.wasm` 资源必须显式加进 `CopyPlugin` 的 patterns**，否则发布包里会缺文件。见 `05-SiYuan插件接口.md` 第 6 节。
