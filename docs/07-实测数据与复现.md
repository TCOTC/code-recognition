## 4. Magika 表现（在 betlang 的测试语料上）

脚本：`scripts/bench.mjs`。语料是 betlang 自带的
`tests/fixtures/languages/*`（48 个文件，每个 57–772 字节）。

```
model=standard_v3_3 labels=214
beg=1024 end=1024 block=4096 min_for_dl=8

samples=48
raw_top1_correct=47/48 (97.9%)  txt/unknown_fallback=1
raw_accuracy_on_decoded=97.9%
subset48_argmax_correct=48/48 (100%)
latency_ms_per_call=3352.95 ~ 4826.08
```

逐条结果里唯二的“异常”：

| 文件 | 期望 | Magika 输出 | 说明 |
|---|---|---|---|
| `html.html`（334 B） | html | **txt**（score 0.325） | 低于阈值被降级，这是 Magika 的设计 |
| `vb.vb`（692 B） | vba | vba | 与 betlang 的 `vba` 标签一致，是文档作者的期望值写错了 |

**公平性警告**：这批语料是 betlang 自己的测试集（它的 CI 断言全部命中），
所以对 betlang 有利，**不能**用来比较准确率。
唯一可信的准确率对比是 betlang 模型卡的 34,087 文件留出集：
`test_fs_accuracy=0.942353`、`test_teacher_parity=0.944055`（与 Magika v3.3 教师一致率）。

## 5. 长尾兜底方案对照（补充实验）

评估对象：`hljs.highlightAuto` 能不能兜住 betlang 覆盖不到的长尾语言。
语料：本机真实文件 **103 个 / 11 种长尾语言**，每个文件取前 1024 字节。

| 方案 | 候选集 | 准确率 | 平均耗时 |
|---|---|---|---|
| highlightAuto A | 全部 201 | 14.6% | 37.5 ms |
| highlightAuto B | 未覆盖的 155 | 15.5% | 24.0 ms |
| highlightAuto C | 155 去掉 moonbit / dns | 33.0% | 22.9 ms |
| highlightAuto D | 只留真值 11 种（**作弊上限**） | 81.6% | 1.5 ms |
| **关键词规则表** | 11 种语言 / 约 40 条正则 | **61.2%** | **0.094 ms** |

污染源诊断（`scripts/moonbit-probe.cjs`）：

```
不含 third-languages.js:  Rust   -> dns(25)      第二名 rust(17)
                          Python -> dns(28)      第二名 dart(22)
                          Go     -> dns(22)      第二名 go(21)
含   third-languages.js:  Rust   -> moonbit(35)  第二名 dns(25)
                          Python -> moonbit(42)  第二名 dns(28)
                          Go     -> moonbit(27)  第二名 dns(22)
```

`moonbit` 语法声明了 144 个泛用关键字，relevance 被累加到超过真实语言；
它由 SiYuan 的 `third-languages.js` 引入。详细分析见 `03-识别引擎选型.md` 第 8 节。

复现脚本：`scripts/fallback-eval.cjs`、`scripts/fallback-eval2.cjs`、
`scripts/rule-vs-hljs.cjs`、`scripts/moonbit-probe.cjs`。
